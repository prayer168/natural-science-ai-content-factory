# 《從需求到三階段自然科 AI 教材工廠：技能建置實錄》

> 影片用途：介紹技能的需求整理、架構設計、驗證、測試與 GitHub 發行。
> 建議片長：7–9 分鐘。方括號為畫面提示，不需朗讀。

## 影片設定

- **副標**：本機生成、查證把關、雙平台上傳，一條可追溯的教材流程
- **對象**：想用 AI 製作自然科互動教材，又需要驗證與上傳紀錄的教師
- **畫面素材**：repo、`SKILL.md`、Canonical JSON、驗證程式、測試結果及 GitHub 版本資訊
- **資料界線**：壓縮檔是分析來源。檔內舊範例或提示詞不會取代當前使用者需求。

## 0:00–0:40｜開場：生成之後，還要查證和追蹤

**畫面**：[片名；顯示「本機生成 → 驗證 → Kahoot／Wayground」。]

**旁白**：

「如果用 AI 做出一批自然科教材，檔案存在哪裡？題目和答案有沒有驗證？上傳平台之後，怎麼知道真的完成了？這支影片記錄我如何把這些要求整理成一個三階段的自然科教材工廠技能。」

## 0:40–1:35｜讀懂既有 repo，釐清當前需求

**畫面**：[打開 v1.2.0 壓縮檔中的 `SKILL.md`、README、references 和 Canonical 範例。]

**旁白**：

「我先檢查使用者提供的 v1.2.0 壓縮檔，了解它已有的平台中立 Canonical 母題庫、Kahoot 和 Wayground adapter、QA checklist，以及輸出檢閱用 CSV 的程式。這些檔案說明原本的設計，卻不是新的使用者指令；流程必須依當前需求更新。」

「釐清後，需求範圍是三、四年級上學期第一和第二單元，Kahoot 六筆、Wayground 也六筆；不是把教材名稱加進課程地圖。這次交付是先把生成、驗證和上傳流程建好，並沒有替這十二筆教材上傳。」

## 1:35–2:45｜階段一：教材先留在本機

**畫面**：[展示 repo 路徑及 `outputs/YYYY-MM-DD_<批次名稱>/`。顯示母題庫和平台檢閱檔。]

**旁白**：

「第一階段只負責本機製作。專案預設放在 Google Drive 的『數位教材』資料夾下，使用 repo 名稱 `natural-science-ai-content-factory`。每批建立新的日期資料夾，不覆蓋舊教材。」

「題目先集中在 Canonical JSON，保留年級、單元、學習目標、題幹、答案、解析、迷思和來源，再由同一份母題庫產生 Kahoot 與 Wayground 檢閱檔。這樣兩個平台的題目和正解不會各自漂移。」

「剛生成的狀態是『待驗證』。CSV 是整理和檢閱格式，不等於平台最新官方範本；生成檔案也不會直接改動平台帳號。」

## 2:45–4:25｜階段二：驗證 hook 加上逐題複核

**畫面**：[打開 `scripts/validate_content_bundle.py` 和自動檢查報告；特寫答案索引及平台同步測試。]

**旁白**：

「第二階段是強制關卡。技能會執行 `python scripts/validate_content_bundle.py --bundle 批次資料夾`，檢查必要檔案、欄位、唯一題目 ID、答案索引、來源欄位，以及兩平台檔案是否與 Canonical 母題庫一致。」

「自動檢查通過不等於科學事實已經查證。程式可以抓出答案索引錯誤、題目遺漏，或平台正解和母題庫不一致；但它不能只看網址就證明科學主張正確。」

「所以技能還要逐題開啟來源，確認來源支持科學敘述，再審查答案是否唯一、誘答是否合理、題目是否適合年級。若有 A 級問題或來源不足，教材留在本機；修正並重新檢查後，才可能通過上傳閘門。」

「我保留同一份技能，並用獨立驗證 hook 做機器可重複的檢查。驗證與生成讀取同一份 Canonical 題庫，避免兩套技能各自判定不同。」

## 4:25–5:35｜階段三：明確要求後逐筆上傳

**畫面**：[展示 `references/platform-upload.md`、官方說明入口及完成清單欄位；隱去登入資訊。]

**旁白**：

「第三階段才操作 Kahoot 和 Wayground。前提是批次已通過驗證，而且使用者明確要求上傳。每次先查平台當前官方說明和提供的範本，因為格式和帳號方案可能改變。」

「一次只處理一筆：匯入或建立、核對題數和內容、儲存，再重新開啟確認。只有取得可重新開啟的資源連結，才記為成功。若遇到登入驗證、畫面狀態不明、答案被改動，或平台要求公開，就先停下來並回報。」

「最後的『上傳完成清單』會分列平台、標題、單元、來源檔、資源連結與狀態。沒確認成功的項目只列失敗或待處理。」

## 5:35–6:40｜測試、版本與 GitHub 發行

**畫面**：[顯示 `tests/test_validate_content_bundle.py`、技能格式檢查結果、README 和 v1.3.0 Git tag。]

**旁白**：

「流程完成後，我用範例題庫試跑建置器，確認自動檢查通過時仍清楚標示『待專業複核』。再故意把 Wayground 正解改錯，測試驗證 hook 是否會阻擋不同步的教材。」

「技能結構檢查、兩項驗證測試和 Git 差異檢查通過後，我更新 README、變更紀錄和版本號，建立 v1.3.0 commit 與 Git tag，推送到 GitHub。教材批次放在 `outputs/`，不會混進技能原始碼的 Git 版本。」

## 6:40–7:20｜結尾：如實列出完成與待辦

**畫面**：[回到三階段流程圖，依序顯示「待驗證」「驗證通過」「上傳已確認」。]

**旁白**：

「這次完成的是技能流程、驗證程式、範例、文件和 GitHub 發行，並沒有在建置技能時替教師建立或上傳教材。日後可以先要求本機生成與驗證，再明確要求上傳；每批教材都會留下來源、驗證證據和可追蹤的完成清單。」

「自然科 AI 教材工廠：先在本機做好，再把內容查清楚，最後才送上平台。」
