# 本機驗證閘門

驗證分為可重現的程式檢查與逐題的專業審查；兩者均通過才允許上傳。程式檢查不會自行證明科學事實正確。

## 執行

```powershell
python scripts/validate_content_bundle.py --bundle "<批次資料夾>"
```

命令檢查 `canonical.json`、`kahoot-ready.csv`、`wayground-ready.csv`、`teacher-notes.md`，並將程式檢查結果寫入 `自動檢查報告.md`。若有阻擋問題，程序以非零狀態結束；先修正資料，再重新執行。程式檢查通過只表示自動檢查通過，並不代表教材已可上傳。

## 自動阻擋項目

- JSON 無效、題目欄位缺漏、ID 重複、題型／階段／狀態無效。
- 題幹或選項空白、答案索引超出範圍／重複、單選題正解數不是一個。
- 題目不是 `verified`，或查證來源未列出標題、網址與支持的主張。
- Kahoot／Wayground adapter 缺漏；Wayground 缺少 fallback；兩份平台檔缺題、重複或題目／正解／題型與 Canonical 不一致。
- 預期輸出檔不存在或 CSV 欄位無法讀取。

## 必須由技能完成的逐題審查

1. 開啟每個來源網址，確認內容實際支持所列主張。連結失效、來源不可靠或證據不足時，不得標 `verified`。
2. 檢查答案是否唯一且可辯護、誘答是否對應合理迷思、題幹是否年級適切、圖表／實驗推論是否有證據。
3. 檢查課綱或教材版本主張是否由來源支持；明載、推論與外部證據要分清楚。
4. 記錄每題查證結果及修正到 `驗證報告.md`，任何 A 級問題均阻擋該題上傳。
5. 驗證後重新執行程式 hook，確認最終檔案與已審閱 Canonical 題庫一致。

技能完成逐題複核後，建立或更新 `驗證報告.md`：結論只能為 `BLOCKED` 或 `PASS`，且 `PASS` 必須同時附上自動檢查及逐題查證結果。若只有部分題目通過，可分批將通過題目複製到另一個新批次，再單獨驗證；不可將整批標為通過。
