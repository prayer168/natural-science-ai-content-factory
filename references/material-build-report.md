# 教材建置報告規格

每批教材建立一份 `教材建置報告.md`，作為生成、課綱對照、查證、驗證、修訂及平台發布的索引。報告由 `scripts/build_material_report.py` 依批次 manifest、Canonical 題庫、驗證報告及實際輸出檔案產生；不得用猜測或檔案時間戳補欄位。

## 必要欄位

- 批次名稱、教材名稱、建置日期、報告產生日期、產出狀態。
- 年級、學期、出版社與版本、單元／活動及題數。
- 題型：Canonical 題型分布與 Kahoot／Wayground adapter 題型，以及 Wordwall 建議活動形式；說清楚檢閱檔不是官方匯入範本、Wordwall 稿是人工建置設計。
- 課綱對照：學習內容代碼與學習表現代碼，附官方文字、教材題目／活動的對應理由、課綱來源及核對狀態。不可由年級、單元名稱或題幹自行推定出版社的精確編排。
- 難易度：依 Canonical `difficulty` 統計各層題數，列出難度尺度及其為本批設計標籤、不是官方標準。
- 本機絕對資料夾位置與每個產出檔名、用途、位元組數及 SHA-256。
- 科學來源與逐題來源覆蓋、程式 hook 狀態、逐題專業複核狀態、問題與修正紀錄。
- Kahoot／Wayground 建立／上傳狀態；Wordwall 人工稿完成狀態與實際平台建立狀態分開記錄。只有實際確認後才列資源識別碼或可重開網址。
- 限制與待補資料，例如學校採用版本、教材頁碼、官方平台當期匯入格式。
- 限制與待補資料，例如學校採用版本、教材頁碼、官方平台當期匯入格式。

## 證據與狀態規則

1. 建置日期取自 manifest 的 `build_date` 或批次明確日期。缺值寫「待補」；報告產生時間另列，不能以產生報告的日期冒充教材建置日期。
2. 課綱代碼須以課綱來源原文核對。manifest 應為每項代碼保存 `code`、`description`、`alignment_note` 與 `source_url`；沒有完整對照證據時標為「待核對」，不可虛構代碼或文字。
3. 題型、難度、題數、來源、題目 ID、答案索引及檔案雜湊由實際檔案計算，不接受手填數字覆蓋。
4. `AUTO PASS` 代表程式 hook 通過；`MANUAL PASS` 代表驗證報告明確記錄逐題複核通過。兩者分開呈現。檔案缺失、來源缺漏或報告不是 PASS 時，不得把教材狀態標成「驗證通過」。
5. 後續修訂後重新計算雜湊並重跑驗證；在 manifest 的 `revision_history` 追加日期、檔案、變更原因、驗證結果。不得覆寫舊批次。
6. 尚未上傳時明確寫「尚未上傳」。若 CSV 未以當期官方範本驗證，不可稱為可直接匯入。

## 建議執行

```powershell
python scripts/build_material_report.py --batch "outputs/YYYY-MM-DD_<批次名稱>"
```

報告涵蓋整批各單元，含彙總表、逐題課綱與來源追蹤表、檔案清冊與雜湊、驗證／修訂／平台狀態。每次完成生成、驗證、修訂或上傳後重新執行，以反映最新且可追溯的實際狀態。
